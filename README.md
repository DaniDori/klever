# Клевер — магазин одежды ручной работы

Витрина и админ-панель на чистых HTML, CSS и JavaScript. Данные хранятся
в SQLite, сервер — на Node.js. Сборки нет, зависимостей нет: всё, что нужно
серверу, уже встроено в Node 22.5+ (включая SQLite).

## Как запустить

```bash
npm start
```

Или то же самое без npm:

```bash
node server/server.js
```

Затем открыть http://localhost:8080/

При первом запуске сервер сам создаёт базу `server/klever.db`, заливает в неё
демо-наполнение и ставит пароль админки `klever`. Дальше база живёт своей
жизнью — `seed.json` больше не читается.

Двойным кликом по `index.html` сайт **не откроется**: страницы берут наполнение
у сервера, без него будет пустая витрина с предупреждением.

Настройки — переменные окружения, все со здравыми значениями по умолчанию:

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `PORT` | `8080` | порт |
| `HOST` | `0.0.0.0` | адрес прослушивания |
| `DB_PATH` | `server/klever.db` | файл базы |
| `UPLOADS_DIR` | `uploads` | папка с фотографиями |
| `ADMIN_PASSWORD` | `klever` | пароль, но только при создании пустой базы |
| `SECURE_COOKIES` | по протоколу | `1` — всегда ставить куке флаг `Secure` |

Развёртывание на сервере — в [DEPLOY.md](DEPLOY.md).

## Админ-панель

Адрес: `admin.html`, стартовый пароль — **klever** (меняется в разделе
«Настройки», и это первое, что стоит сделать).

Открытой ссылки на админку на сайте нет. Вход — **пять быстрых нажатий на
логотип** (в шапке или в подвале, работает и мышью, и пальцем). После третьего
нажатия клевер слегка поворачивается — видно, что счётчик пошёл. Обычный клик
по логотипу по-прежнему ведёт на главную, просто с паузой в 450 мс: за неё
скрипт понимает, что нажатие одиночное. Настройки — `SECRET_CLICKS` и
`SECRET_GAP` в начале блока «Тайный вход» в [ui.js](assets/js/ui.js).

Разделы: Обзор, Товары, Категории, Баннеры, Страницы, Заявки, Настройки, Данные.

Адрес товара в ссылке (`product.html?id=plate-poleva`) руками не задаётся —
он собирается из названия при сохранении. Пока название не меняли, адрес
остаётся прежним; переименовали вещь — адрес пересоберётся. Если такой адрес
уже занят другим товаром, к нему добавится номер: `plate-poleva-2`.

Что важно понимать:

- Всё наполнение лежит в **базе на сервере**. Правку сразу видят все посетители,
  а панель открывается с любого устройства — телефона, ноутбука, чужого браузера.
- Пароль в базе не хранится: только необратимый отпечаток (scrypt с солью).
  Восстановить забытый пароль нельзя — можно только задать новый, см. DEPLOY.md.
- Вход держится на httpOnly-куке: из JavaScript её не прочитать. Смена пароля
  закрывает все остальные открытые сессии.
- Фотографии уменьшаются в браузере до 1200 px (и до 700 px для карточек
  каталога), а потом кладутся файлами в `uploads/`. Лимита в 5 МБ больше нет —
  упереться можно только в место на диске.
- «Данные» показывают размер базы и папки с фото, находят снимки, на которые
  больше никто не ссылается, и отдают всё наполнение одним JSON.

### Что защищено

- Публично доступны ровно два адреса: снимок наполнения и приём заявки.
  Всё под `/api/admin/` требует сессии.
- Заявки покупателей в публичный снимок не попадают — только в панель.
- Приём заявок ограничен: 20 штук в час с одного адреса.
- Подбор пароля ограничен: 10 попыток за 15 минут с одного адреса.
- Любой запрос на запись обязан прийти с самого сайта (заголовок `X-Klever`) —
  это отсекает отправку форм с чужих страниц.
- Наружу не отдаются ни база, ни исходники сервера, ни `img/original/`.

## Корзина и заказы

Покупатель набирает вещи (кнопка «В корзину» на карточке товара) или заказывает
одну вещь сразу. Корзина живёт в `localStorage` браузера покупателя, ключ
`klever.cart` — это единственное, что осталось на стороне покупателя, и так
и должно быть: чужая корзина никому не нужна.

При оформлении заказ уходит двумя путями сразу:

1. **В базу** — появляется в разделе «Заявки» со списком вещей, размерами,
   количеством, способом доставки и суммой.
2. **Письмом** через бесплатный сервис-посредник, если он настроен.

Пути независимы, и покупателю показывают ровно то, что произошло: дошло обоими —
«Заказ отправлен»; дошло только до базы — «Заказ принят»; не дошло никуда —
честное «Заказ не дошёл» и кнопка «Отправить в Telegram» с готовым текстом.
Потерять заказ молча нельзя.

### Вычеркнуть товар при оформлении

В форме оформления у каждой строки есть крестик. Вычеркнутый товар сразу
выпадает из суммы, но пять секунд остаётся на экране с кнопкой «Вернуть · 5»
и обратным отсчётом. Только после этого он убирается из корзины окончательно.
Если вычеркнуть всё, кнопка отправки гаснет и пишет «Нечего заказывать».
Длина паузы — `UNDO_MS` в [ui.js](assets/js/ui.js).

### Настройка почты

Админка → Настройки → «Письма о заказах».

| Вариант | Что нужно | Плюс | Минус |
|---|---|---|---|
| **Не отправлять** | ничего | заказы просто копятся в панели | нужно заходить и смотреть |
| **Web3Forms** | бесплатный ключ с web3forms.com | адрес почты не виден в коде, 250 писем/мес | нужна регистрация |
| **FormSubmit** | только адрес почты | без регистрации | адрес виден в коде, первое письмо активирует адрес |

Кнопка «Отправить пробное письмо» проверяет настройку сразу.

Что важно понимать:

- Письмо — не единственный путь: заказ в любом случае лежит в «Заявках».
  Даже вариант «Не отправлять» ничего не теряет.
- Ключ и адрес видны в коде страницы — спамеры могут расходовать лимит.
  У обоих сервисов есть капча и фильтры, включаются в их панели.
- Письма иногда попадают в «Спам» — проверьте папку после первого заказа.
- Оплаты онлайн нет: заказ — это заявка, дальше вы связываетесь с покупателем.

## Структура

```
assets/css/tokens.css   палитра, шрифты, отступы, тени
assets/css/main.css     витрина
assets/css/admin.css    админ-панель
assets/js/store.js      чтение с сервера и запись через API
assets/js/cart.js       корзина покупателя
assets/js/mail.js       отправка заказа на почту через сервис-посредник
assets/js/ui.js         шапка, подвал, модалки, заглушки, разметка текста
assets/js/home.js       главная
assets/js/catalog.js    каталог и фильтры
assets/js/product.js    карточка товара
assets/js/pages.js      текстовые страницы и контакты
assets/js/admin.js      админ-панель

server/server.js        HTTP: статика, маршруты, резервные копии
server/db.js            SQLite: схема, чтение и запись
server/api.js           обработчики /api
server/auth.js          пароль, сессии, защита от перебора
server/seed.json        демо-наполнение для первого запуска
server/klever.db        база (появляется при первом запуске)
server/backups/         копии базы за две недели
uploads/                фотографии, загруженные через админку
```

Точка соединения — одна: `Store` в [store.js](assets/js/store.js). Чтение
осталось мгновенным (страница подключает `/api/content.js`, который кладёт
готовый снимок в `window.KLEVER_DATA`), запись ушла в сеть и возвращает промис.
Остальные скрипты витрины не знают, что данные теперь общие.

## Палитра

Молочный `#FBFAF6`, лён `#F1ECE2`, шалфей `#8FA98A`, клеверный `#4F6B4A`,
пыльно-розовый `#E9D5CD`, туман `#D4DEDB`, песок `#E8DCC8`.

Все цвета — переменные в `tokens.css`, менять их достаточно в одном месте.

## Свайпы

Пальцем на телефоне и перетаскиванием мышью на десктопе:

- **Баннеры на главной** — листаются свайпом, автосмена перезапускается.
- **Фото товара** — свайп по большому снимку, точки под фото, миниатюры
  подсвечиваются синхронно.
- **Карточки в каталоге** — если у товара загружено больше одного фото,
  их можно листать прямо в карточке; появляются точки. Жест не срабатывает
  как клик — на страницу товара карточка уводит только при обычном нажатии.

Вертикальная прокрутка страницы жестами не перехватывается: свайп считается
горизонтальным только если движение по X больше, чем по Y.

## Как устроена главная

1. **Плакаты** — карусель баннеров из админки, листается свайпом и точками.
2. **Три кнопки** — «Каталог», «Женщинам», «Мужчинам». Ведут в каталог
   с уже выбранным фильтром: `catalog.html?gender=women`. Под каждой —
   счётчик вещей, а если их нет, пишется «скоро».
3. **Ассортимент** — первые восемь вещей по порядку из админки и ссылка
   на весь каталог.
4. **Пошив по меркам** — форма заявки.

У каждого товара есть поле **«Кому»** (женщинам / мужчинам) — оно задаётся
в карточке товара и определяет, в какой раздел вещь попадёт. В каталоге это же
поле работает как фильтр «Кому». Счётчик под кнопкой считается на лету: пока
вещей нет, там «скоро», а как только появится первый товар с нужной пометкой —
подпись сменится сама.

## Фотографии

Живые снимки лежат в `img/` в двух размерах:

| Файл | Где используется |
|---|---|
| `dress-fern.jpg` | Платье «Полева» + первый баннер |
| `dress-emerald.jpg` | Платье «Луговое» |
| `dress-black.jpg` | Платье «Ночь» + третий баннер |
| `sundress-daisy.jpg` | Сарафан «Ромашка» + страница «О мастерской» |
| `suit-cherry.jpg` | Костюм «Вишня» + второй баннер |

Версии `-sm.jpg` (525×700, 50–80 КБ) идут в карточки каталога, полные
(1050×1400) — в галерею товара и плакаты.

**Фото не обрезаются.** Снимки бывают вертикальные, квадратные и с телефона,
поэтому они вписываются в плитку целиком (`object-fit: contain`), а свободное
место заливается белым. Так на телефоне не отрезает головы и подолы. Исключение —
сгенерированные заглушки: они заполняют плитку полностью, это просто фон.

Исходники в `img/original/` — в сайт не попадают, но пусть лежат: пригодятся,
если понадобится перекадрировать. Общий вес снимков для сайта — около 1,4 МБ вместо 12 МБ
исходников.

Чтобы добавить новые, загрузите их через админ-панель: браузер сам уменьшит
снимок до 1200 px, сделает копию на 700 px для карточек каталога и отправит оба
файла на сервер — в папку `uploads/`. В базе останется только путь, поэтому она
не пухнет, а фотографии кешируются браузером навсегда (имена уникальные).

Файлы из `img/` — это демо-набор; можно класть туда свои и указывать путь
вручную, но через панель проще.

## Заглушки вместо фото

Пока фотографий нет, картинки генерируются на лету: пастельный градиент,
нити «ткани» и силуэт трилистника. Как только вы загрузите фото через
админ-панель, заглушка заменится на него.
